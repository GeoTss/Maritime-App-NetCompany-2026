# Port Call and Storm Avoidance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (hackathon scope, below) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bunker stop becomes a whole port call (fuel, provisions, charts and publications, sludge and sewage delivery, port dues, clearance, pre-arrival notices), costed and timed in the stop plan. Heavy weather becomes a limit the route and speed must respect, with a route round the storm.

**Architecture:**
- **Domain.** New pure modules `areas.ts`, `port-call.ts` and `storms.ts`. `evaluateStopPlan` gains a port-call pass, and the optimiser gains the `heavy_weather` reason.
- **Data.** One migration: `vessels.stores` and `ports.call_terms` (jsonb, Zod-checked), plus a `nautical_items` table seeded from the user's supplier checklist.
- **Wiring.** `packages/db/src/route-plan.ts` feeds the stores, terms and catalogue into the optimiser input and adds a storm-detour candidate. The API only turns results into facts.
- **Approvals.** The existing voyage instruction carries the jobs; its execution drafts the agent request and the notices.

**Tech Stack:** TypeScript 6 ESM, Zod (`packages/shared`), Vitest, Drizzle + Postgres (`packages/db`), Hono (`apps/api`), React 19 + Vite + Tailwind 4 + shadcn + MapLibre (`apps/web`), Playwright (`e2e/demo.spec.ts`).

**Spec:** `docs/superpowers/specs/2026-11-19-port-call-and-storms-design.md`. Read it first. "Goal N" below means the spec's goal N.

## Review Focus

1. **A vessel with no stores data** (AIS ships; any vessel whose `stores` is null): `portCall` is `null` and the stop plan behaves exactly as today. → Task 3 test `no stores, no port call`.
2. **No weather** (null grid, or beyond the forecast): there is no `heavy_weather` reason, no storm cells and no `S` candidate. → Task 4 test `no weather, no storm`.
3. **The detour equals an existing candidate, or the graph cannot go round**: no duplicate `S` candidate; the plan still returns. → Task 6 test `detour deduplicated`.
4. **A stop too close for its notices**: the plan is infeasible with `notice_overdue` and does not throw. A non-EU stop has no EU waste notice. → Task 2 tests `overdue notice` and `non-EU stop has two notices`.
5. **"m³" in an answer**: "11.0 m³" passes the release gate when cited, and the "3" in "m3" is not read as an uncited number. → Task 7 test `m3 unit`.

### Task 2: Domain: areas and port-call projections

**Files:**
- Create: `packages/domain/src/areas.ts`, `packages/domain/src/port-call.ts`, plus `*.test.ts` for each; export both from `index.ts`

**Interfaces (produces):**
- `areaPasses(points: LatLon[], stepNm: number, areas: { id: string; boxes: Box[] }[]): { areaId: string; enterNm: number }[]`. For each area the route enters, the distance along the polyline of the first sub-step midpoint inside any of its boxes. Sorted by `enterNm`, then id. Track 3 reuses it.
- `provisionsDaysLeft(stores: VesselStores, hours: number): number` = `(provisionsPersonDays − crew·hours/24) / crew`.
- `sludgeGeneratedM3(fuelMt: GradeAmounts): number` = Σ `fuelMt[g] · SLUDGE_M3_PER_MT[g]`.
- `sewageGeneratedM3(crew: number, portHours: number): number` = `crew · SEWAGE_M3_PER_PERSON_DAY · portHours/24`.
- `outdatedItems(onBoard, catalogue: NauticalItem[], passes, stop: { nm: number; position: LatLon }, timeAtNm: (nm) => IsoDateTime): OutdatedItem[]`.
  - Considers catalogue items whose area the route enters.
  - An item is outdated when it is missing on board, or its on-board `editionDate` is before the current one.
  - `inTime` = `stop.nm ≤ enterNm`, **or** the stop position lies in one of the item's boxes.
  - `neededAt` = `timeAtNm(enterNm)`.
- `preArrivalNotices(arriveAt: Date, portIsEu: boolean, now: Date): PreArrivalNotice[]`. Agent appointment and security always; the EU waste notice only at EU ports. `dueAt = arriveAt − NOTICE_LEAD_HOURS[kind]`, and `overdue = dueAt < now`.
- `portCallPlan(a: PortCallArgs): PortCallResult & { reasons: StopPlanReason[]; serviceHours: number }`, where
  `PortCallArgs = { stores, terms, portIsEu, now, arriveAt, hoursToStop, hoursToEta, stayHours, fuelToStopMt: GradeAmounts, fuelTotalMt: GradeAmounts, outdated: OutdatedItem[], bunkeringHours }`.
  - **Provisions.** Needed when `provisionsDaysLeft(stores, hoursToEta) < PROVISIONS_RESERVE_DAYS`. Qty = `crew·PROVISIONS_TARGET_DAYS − (provisionsPersonDays − crew·hoursToStop/24)`.
  - **Sludge.** Needed when `sludgeM3 + sludgeGeneratedM3(fuelTotalMt) > WASTE_MAX_FILL·sludgeCapacityM3`. Delivered qty = `sludgeM3 + sludgeGeneratedM3(fuelToStopMt)`.
  - **Sewage.** Needed when `sewageM3 + sewageGeneratedM3(crew, stayHours) > WASTE_MAX_FILL·sewageCapacityM3`.
  - **Charts.** Needed when `outdated.length > 0`. Qty = item count; cost = Σ `priceUsd`.
  - **Done.** A needed job is done when the port can do it (`stores` for provisions and charts, `wasteReception` for sludge and sewage). Otherwise add `provisions_unavailable` or `waste_reception_unavailable`. Charts not available only warns: the items stay listed, with `done: false`.
  - **Costs.** `costLines` = port dues + each done job's cost + `eu_waste_fee` when `portIsEu`. `extraCostUsd` = their sum.
  - **Time.** `serviceHours = max(bunkeringHours, storesHours if a stores job is done, wasteHours if a waste job is done)`.
  - **Notices.** Any overdue notice adds `notice_overdue`.
  - **Levels at ETA.** `*AtEta` are the levels at the destination after any delivery.
